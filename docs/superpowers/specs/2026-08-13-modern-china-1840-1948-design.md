# 中国近代史 1840-1948 年度事件补全设计

## 目标

补全项目中的中国近代史年度重大事件内容。1840-1920 年按关键节点年补录，1921-1947 年做到每年都有中国与世界重大事件，1948 年保持现有已完成成果不变。补全后，相关年份应能在主时间线中进入年度专页，数据通过现有 Schema 校验，并在 `check.md` 留下逐年审查记录。

## 范围

- 1840-1911 年中国事件写入 `data/events/qing.yaml`。
- 1912-1947 年中国事件写入 `data/events/minguo.yaml`。
- 世界事件统一写入 `data/world/modern.yaml`。
- 为新增年度专页创建 `src/pages/<YEAR>.astro`，复用 `AnnualEventsPage`。
- 在 `src/components/Timeline.astro` 与 `src/components/AxisCell.astro` 注册新增年度入口。
- 必要时在 `src/pages/index.astro` 添加代表性快捷入口，但不为 1840-1947 的每一年都堆叠首页入口。
- 每个完成年份都追加 `check.md` 审查记录。

不改 1948 年已完成数据、图片、测试和专页，不调整现有视觉设计，不重构年度页组件。

## 年份策略

### 1840-1920 关键节点年

这段不要求逐年覆盖，只收影响中国近代史结构转折的年份。初始关键节点清单为：

| 阶段 | 年份 |
|---|---|
| 晚清开端与条约体系 | 1840、1842、1851、1856、1860、1861 |
| 洋务、边疆与甲午前后 | 1872、1884、1885、1894、1895、1898 |
| 庚子、清末新政与革命 | 1900、1901、1905、1908、1911 |
| 民国初建与五四前后 | 1912、1915、1917、1919、1920 |

若来源核验中发现某个节点年缺乏足够事件密度，可以只补中国事件，不强行补世界事件。若发现同等重要遗漏，可以追加到清单，但必须在设计执行记录中说明原因。

### 1921-1947 逐年覆盖

1921-1947 是连续补全年段，每一年至少收录中国重大事件；世界事件按同一标准补充，不为凑数降低重要性。1921、1931、1937、1945 等既有条目保留并审校字段完整性，缺少 `sources` 或 `tags` 时补齐。

建议按批次推进：

| 批次 | 年份 | 重点 |
|---|---|---|
| A | 1921-1927 | 中共创建、国共合作、北伐与国民革命 |
| B | 1928-1936 | 南京国民政府、土地革命、九一八、西安事变 |
| C | 1937-1945 | 全面抗战及二战同步世界事件 |
| D | 1946-1947 | 解放战争早期与战后国际秩序 |

1948 作为已完成基准，只在最终总体验收时确认仍然通过测试。

## 数据设计

事件沿用现有 YAML Schema：

```yaml
- id: cn-<slug>-<yyyymm>
  date: "YYYY-MM-DD"
  title: 事件标题
  category: 政治
  importance: 5
  summary: 一到三句话事实摘要
  confidence: 确定
  tags: [标签1, 标签2]
  sources: [来源1, 来源2]
```

中国事件统一使用 `cn-` 前缀新增 ID；既有旧 ID 不强制重命名，除非自动化测试或去重需要。世界事件使用 `w-` 前缀。日期只在来源能支持时精确到日；只能确认年份或月份时保留相应精度。

分类限定为项目现有枚举：`政治`、`战争`、`文化`、`经济`、`灾害`。科技、教育、体育、卫生、思想文化类事件归入 `文化`；外交、会议、政权、制度类事件归入 `政治`。

重要度保持审查 skill 的标准：

- `5`：改变国家道路、战争进程、国际秩序或长期制度结构的历史转折。
- `4`：影响显著但未达到结构性转折的重大事件。
- `3` 及以下：只有在需要保留背景节点时使用，不用于凑满年份。

## 来源与核验

1840-1920 年以权威史料和百科年度页交叉核验为主。优先级为：

1. 新华网、人民网、中国共产党新闻网、中央党史和文献研究院、政府或机构官网。
2. 中文维基百科和英文维基百科年度页、事件页。
3. 专业机构资料，如中国地震局、联合国、世界卫生组织、相关国家档案或纪念机构。

每条新增事件至少应有两个来源名称；若确有权威单一来源且无可替代来源，允许保留但在 `check.md` 说明。不得仅凭搜索摘要、未经核验的大事记网页或无法访问正文的片段写入事件。

## 页面与路由

新增年份专页统一使用：

```astro
---
import AnnualEventsPage from '../components/AnnualEventsPage.astro'
---

<AnnualEventsPage year={YEAR} />
```

每个有专页的年份都加入：

- `src/components/Timeline.astro` 的 `summaryYears`
- `src/components/AxisCell.astro` 的 `hasSummary`

首页只放代表性入口，避免快捷区过长。建议首页入口覆盖 1840、1911、1921、1937、1945、1948。

## 执行流程

每个年份作为独立工作单元：

1. 建立基线：统计该年现有中国事件、世界事件、四星、五星和配图数量。
2. 检索候选：按中国事件、世界事件分别读取权威来源正文和中英文维基年度页。
3. 提交候选清单：列出拟新增、拟修正、拟保留和来源状态。
4. 写入最小修改：更新对应 YAML，创建专页并注册路由。
5. 审查记录：在 `check.md` 追加本年来源、修改、未解决问题和验证结果。
6. 验证：运行数据校验和相关测试。

试点先做 1921 年。1921 年通过用户验收后，再按批次连续推进。连续阶段每完成一个年份都记录并验证，然后进入下一年。

## 测试与验收

新增或调整测试按风险分层：

- 试点年份新增专门测试，覆盖事件数量下限、字段完整性、关键 ID、专页存在和路由注册。
- 批量阶段可以使用参数化测试覆盖 1921-1947 的逐年存在性和字段完整性，避免为每年复制测试文件。
- 1948 年现有测试保持不变。

每个批次完成后运行：

```bash
npm run validate
npm test
```

不运行 `npm run build`，因为项目审查 skill 明确禁止在年度审查流程中执行 build。若后续用户明确要求构建验收，再单独执行。

## 风险与控制

- 早期年份来源数字化不足：如实记录来源缺口，不为凑数加入低可信事件。
- 旧数据字段不完整：逐年审查时补齐 `sources`、`tags`、`confidence` 等字段，但避免大规模无关格式化。
- 年份路由数组过长：本阶段沿用现有数组模式，不在本任务中重构为数据驱动。
- 配图工作量外溢：本阶段以事件补全为主，只为明确可追溯、许可清楚的五星或重点事件补图；找不到合格图片时保持无图并记录。

## 完成标准

- 1840-1920 关键节点年均完成审查和必要补录。
- 1921-1947 每年都有中国事件，世界事件按重要性补充。
- 新增年份专页和主时间线入口可用。
- `check.md` 有逐年记录。
- `npm run validate` 通过。
- `npm test` 中与本任务相关的断言通过；若存在既有无关失败，必须明确记录失败文件和原因。
