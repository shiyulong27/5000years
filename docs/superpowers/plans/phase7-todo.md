> 逐条完成、逐条改状态。完成一条就把状态改成 ✅ 并填日期；卡住标 ⛔ 并写原因。

## 执行约定（必读）

1. 动手前先读 `docs/superpowers/plans/2026-08-04-history-timeline-plan.md` 的
   「已验证结论」与各数据文件顶部注释——模型约定（concurrent、parent、
   confidence/dispute、region 叠画）都在那里。
2. **纯数据条目**：改完跑 `npm run validate`。errors 必须为 0；新增 warnings
   要么处理、要么在 YAML 注释里说明为何是预期。
3. **史实自查**：用 `docs/prompts/data-review.md` 的模板对自己写的条目过一遍。
   凡 confidence ≠ 确定 必带 dispute，「有争议」不许空标。
4. **结构性条目**（动 `src/`、`astro.config.mjs`、workflow）：必须
   `npm test` 与 `npm run build` 全绿，并用 playwright 截图目检。
5. 每条一个 commit，消息格式跟随现有历史（`feat(data): …` / `ci: …`）。
6. 年代从通行说法；有异说的按争议机制标注，不伪造精确。

## 模型分工建议

- **A/B/C 组（数据录入）可由轻量模型执行**（如 deepseek-v4-flash 一类）：
  照现有 YAML 样例仿写，`validate` 会兜住结构错误，review 提示词兜住一部分史实。
- **D 组与任何「改 src/ 的事」用强模型**：布局回归、校验器规则、CI 配置
  这类错误测试不一定兜得住，返工成本高。
- **全量复审（D4）用强模型或人工抽查**，轻量模型的自查只做第一遍。

## A. 中国数据延伸（按朝代顺序）

- ⬜ A1 南北朝（420–589）
  南朝宋齐梁陈 + 北朝（北魏→东魏/西魏→北齐/北周）。**并存政权须标
  concurrent**（三国、晋-吴已有样例）。事件每朝 3–6 条，重统一与制度。
  验收：validate 绿；南北并立时段横幅各出一条（截图目检）。
- ⬜ A2 隋（581–618）
  开皇之治、科举雏形、大运河、隋末民变。验收：validate 绿。
- ⬜ A3 唐（618–907）
  贞观之治、武周（并入唐条或以 dispute 说明）、开元盛世、安史之乱、
  两税法、会昌灭佛、唐末民变。验收：validate 绿 + 事件≥10。
- ⬜ A4 五代十国（907–979）
  五代用根朝代 + concurrent，十国从略（横幅只出五代）。验收：validate 绿。
- ⬜ A5 两宋与辽金西夏（960–1279）
  北宋/南宋为宋之子朝代；辽、金、西夏 concurrent。澶渊之盟、王安石变法、
  靖康之变、绍兴和议、四大发明成熟期事件。验收：validate 绿；并存横幅目检。
- ⬜ A6 元（1271–1368）
  行省制、四等人制（标争议）、元曲。验收：validate 绿。
- ⬜ A7 明（1368–1644）
  洪武建制、郑和下西洋、土木堡、一条鞭法、万历三大征、明亡。验收：validate 绿。
- ⬜ A8 清（1636–1912）
  清前期与晚清分治可考虑子朝代。康乾、四库、鸦片战争、洋务、戊戌、辛亥。
  晚清诸条约年代精确到日者须核对。验收：validate 绿 + 晚清事件逐条 review。
- ⬜ A9 民国（1912–1949）
  民国为朝代记录（concurrent 视与根据地政权并存处理）。五四、抗战、胜利。
  **近现代史表述须中性、采通行教科书说法**；有争议处照标。验收：validate 绿 + 强模型复审。
- ⬜ A10 1949–2026
  建国、改革、入世、奥运、航天等。同上，表述中性。验收：validate 绿 + 强模型复审。
