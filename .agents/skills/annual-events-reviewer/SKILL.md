# 年度重大事件审查

## 核心原则

按年份逐年审查 `data/events/xiandai.yaml` 与 `data/world/modern.yaml`。每个年份都是一个完整审查单元：检索、核验、修改、验证、写入根目录 `check.md`，然后再进入下一年。

必须遵守：

- 事件候选必须能在新华网正文或中英文维基百科年度页、事件页中找到。其他网站不能单独证明事件应被收录；不在新华网发布的新华社稿件不能单独作为候选依据。
- 必须读取可访问的正文，不能根据搜索摘要、标题或印象断言事实。
- 五级事件没有数量上限或配额。只按历史影响判断，不为控制数量而升降级。
- 配图不参与 `importance` 判断；先完成评级，再处理图片。
- 连续审查时，确认问题后直接修正，不逐年等待用户确认。试审阶段只处理用户指定的年份；试审完成后必须暂停，等待用户明确验收通过，不能因测试通过而自行开始连续审查。
- 每年都必须向根目录 `check.md` 追加记录；没有数据修改也必须明确记录“本年无数据修改”。不得覆盖既有记录。
- 不编造日期、数字、引文、来源、图片现场或授权信息。无法核实的内容记录为待核验，不强行修改。

## 涉及文件

- 中国事件：`data/events/xiandai.yaml`
- 世界事件：`data/world/modern.yaml`
- 审查记录：`check.md`
- 年度图片：`public/images/events/<年份>/`
- 相关测试：先检索 `test/`，不要假设每年都存在测试，也不要假设测试硬编码事件 ID。

修改前检查并保留目标文件的编码、BOM 和换行符；使用最小补丁，修改后检查 `git diff`，防止中文乱码和无关格式变化。

开始审查前检查根目录 `check.md`。文件不存在时创建包含年度记录模板的账本；文件已存在时保留原内容并只追加记录。

## 单年审查流程

### 1. 建立基线

提取目标年份全部中外事件，记录审查前的总数、四级数、五级数、配图数。检查工作树，保护用户已有修改。

### 2. 检索候选与防遗漏

至少完成以下检索：

1. 新华网该年国内重大新闻、国际重大新闻及相关专题正文。
2. 中文维基百科年度页。
3. 英文维基百科年度页。
4. 按政治、经济工业、外交军事、科技、文化体育、灾害六个领域补充检索。

六领域仅用于防漏，不要求每个领域都有事件。1978 年以前新华网数字资料不足时，如实记录“未找到”，再以中英文维基百科补查；不得用来源不明的大事记凑数。

仅当候选事件达到项目最低重要性并具有可访问的新华网或维基百科依据时才补录。来源之间冲突时，记录冲突并暂不作高置信度修改。

### 3. 逐条审查

检查：

- 遗漏、重复、拆分或合并不当。
- `date` 的年/月/日精度以及时间、地点、人物、机构、数字、称号。
- `title`、`summary` 的错别字、病句、夸张修饰和前后矛盾。
- `category`、`tags`、`confidence`、`sources` 是否符合实际。
- 是否把纪念活动、例行会议、常规任务或短期热点误评为历史转折。

只在来源支持时增加日期精度。原始资料只能确认月份或年份时，保留月或年精度。

### 4. 区分四级与五级

`importance: 5` 表示历史转折。事件应具有明显的结构性、广泛性和持续性，例如改变国家或国际秩序、开启或终结重要时代/战争/制度，或形成长期改变人类生产生活方式的基础性突破。判断问题是：若从该时代的高级历史叙述中删除此事，是否会造成重大失真？

`importance: 4` 表示重大事件。事件在一国、一区域或一个重要领域影响显著，但没有形成同等级的时代转折，例如重大法律政策、外交峰会、航天节点、国际赛事或严重灾害。

边界规则：

- “首次”“最大”“周年”“引发热议”不自动等于五级。
- 纪念大会、庆典和例行换届通常不评五级，除非同时发生实质性制度或秩序改变。
- 当前新闻热度、已有配图、测试中的既有数量都不是评级证据。
- 不设置每年或中外各自的五级数量上下限；同一标准适用于所有年份。
- 降级与升级都要在 `check.md` 写明比较理由和来源。

### 5. 修正数据与图片

对证据充分的问题直接做最小修改。新增事件遵循现有 YAML 字段和 ID 风格；删除或合并事件前确认不是文件顺序或日期精度造成的误判。

五星事件缺图时按以下顺序处理：

1. 优先查看维基百科条目所用图片对应的 Wikimedia Commons 文件页。
2. 其次查找其他明确允许复用的权威或专业网站图片。
3. 新华网图片可用于内容核验；除非页面明确允许复用或项目已有授权，不得下载到仓库。

每张新增图片都要记录原始页面、作者/机构、许可或授权说明，并写准确图注。不是事件现场的会址、人物资料照或背景图必须在图注中说明。不得使用生成图、文字占位图、与事件无关图片或跨事件复用图片。找不到可靠且可复用的图片时保持无图，并在 `check.md` 记录。

### 6. 同步测试并验证

先检查目标年份相关测试的真实断言。只有数据变化确实改变了被测试的不变量时才同步测试；不要为了让测试通过而保留错误等级，也不要凭空创建固定五星数量。

依次运行：

```bash
npm run validate
npm test -- <相关测试文件>  # 存在相关测试时
npm test
```

禁止执行 `npm run build`。验证失败时继续定位和修复；不得把未执行或失败的验证写成通过。

### 7. 追加 `check.md`

完成目标年份后，按照 `check.md` 中的模板追加：

- 审查范围与前后统计。
- 实际读取的来源 URL 及读取状态。
- 每个新增、删除、合并、字段修正、升级、降级和配图变化。
- 修改前值、修改后值、理由和证据链接。
- 未解决问题、不可访问来源和缺图说明。
- 实际执行的验证命令与结果。
- 没有修改时明确写“本年无数据修改”，同时列出已完成的检索和核验。

试审年份写完记录并验证通过后必须停止，等待用户验收。用户明确启动连续审查后，再按用户指定的年份和顺序逐年执行；试审年份已在 `check.md` 完整记录时默认不重复，除非用户明确要求重审。连续阶段写完当年记录并确认验证通过后，才进入下一年份。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 用五星数量控制评级 | 完全忽略数量，只判断历史影响 |
| 因已有图片保留五星 | 图片与评级分离 |
| 仅看搜索摘要 | 阅读正文；不可访问则记录 |
| 默认年度测试锁定 ID | 先读取真实测试断言 |
| 为配图下载新华网版权图片 | 仅在明确授权时复用 |
| 无修改就跳过 `check.md` | 仍记录来源、结论和验证结果 |
| 修改后等待逐年确认 | 连续审查直接记录并进入下一年 |

## 完成条件

- 遗漏、文字质量、事实准确性和四/五级评级均已检查。
- 所有修改都有新华网或中英文维基百科事件依据。
- 图片来源和许可可追溯，或已明确记录无图原因。
- `npm run validate` 与 `npm test` 实际通过。
- `check.md` 已追加该年份记录，即使本年没有数据修改。
