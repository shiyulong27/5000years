## 一、背景

1. 基础设施已就绪：主 Todo《千古风流·历史人物与诗词名家体系建设》已完成 P-00/P-01/P-02：schema v1、加载校验链路（figureDetails/sources 已入 validateWithWarnings 门禁）、来源登记体系（data/sources.yaml）、李白全景详卷样板（22 条年谱、10 首作品、12 处足迹，validate 零错误）。
2. 需求升级：原方案按金字塔梯队渐进推进（T1 约 20 至 30 人），用户明确要求扩大为所有诗人词人都应有详情，即文学人物详卷成为默认目标而非少数顶流特权。
3. 缺口现状：figures.yaml 文学人物仅 21 人；附录 A 表一显示白居易、韩愈、欧阳修、王安石、陆游、辛弃疾、李商隐、杜牧、孟浩然、刘禹锡等书目专篇人物均无 L1 索引；柳永、周邦彦、姜夔等词人属本需求核心但书目无专篇。
4. 生产成本现实：李白一卷耗时约一个会话时段。批量推进必须分批走同一门禁，防止降质冲量。

## 二、目的

让每一位有可靠史料支撑的诗人、词人（含跨领域文学人物）都拥有结构化全景详卷，使千古风流板块从样板走向成体系的名家谱系，同时不放松李白样板确立的证据、版权与不确定性标准。
## 三、方案

### 推荐方案

名单矩阵冻结 → L1 索引先行 → 按时代批次流水线生产。

1. 名单矩阵：合并三个输入——figures.yaml 现有文学 21 人；附录 A 表一缺失候选带；词史必录而书目无篇目的词人补遗清单。每人标注时期、梯队建议、史料可得性预估（有无正史本传）、批次归属。
2. L1 索引先行：凡进入详卷队列而 figures.yaml 无条目者，先补基础索引，使 has_detail 双向校验可工作。
3. 批次流水线：每批 4 至 6 人，固定流程为逐人史料审计表（正史本传实取）→ sources.yaml 登记 → 编写 detail/{id}.yaml → npm run validate 零错误。先唐宋，再向魏晋南北朝、元明清、近现代延伸。
4. 与主 Todo 分工：杜甫、苏轼、李清照、辛弃疾由主 Todo TASK-007 承接；非文学人物适配留 TASK-012。本 Todo 只管文学人物批量详卷及其 L1 前置。

### 方案步骤

1. 生成名单矩阵并冻结第一批（TASK-001）。
2. 第一批 L1 索引补全并通过校验（TASK-002）。
3. 第一批详卷生产与覆盖统计回写（TASK-003、TASK-004）。
4. 后续批次循环直至矩阵清空或转入维护态（TASK-005 起按批递增）。

### 备选方案与取舍

- 一次性全量生产后统一上线：放弃。单会话无法保证数十人的史料质量，绕过批次门禁会造成难回溯的质量债。
- 只做 T1 不做长尾：与用户需求相悖；史料不足者以 T3 轻量索引兜底并在矩阵中注明原因。
