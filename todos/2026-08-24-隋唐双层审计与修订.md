## 一、背景

两晋南北朝阶段已完成双层审计并交接至隋代。固定 1988 年版目录中第138篇“赵绰依法办事”已进入隋代，第177篇“海龙王钱镠”属于五代十国边界。项目已有 `sui`、`tang`、`events/sui.yaml`、`events/tang.yaml` 和精选王表，但隋唐跨期事件、制度、边疆、社会和安史之乱后结构需要独立复核。

## 二、目的

建立隋唐时期的书目逐篇覆盖映射与独立六维完整性基线，核验统一、制度、边疆、经济社会、思想文化和唐末转折，完成证据充分的最小数据修订、测试和阶段交接。

## 三、方案

### 推荐方案

先以固定书目第138–176篇作为隋唐读者预期索引，再以项目分期和日期窗口联合承载隋、唐及隋唐过渡，独立检查隋唐制度和安史以后政治社会变化。第177篇作为五代边界，不机械纳入唐代。

### 方案步骤

1. 从历史会话原始目录复核第138–177篇，确定隋代起点、唐代主体和五代边界。
2. 用 `loadAll('./data')` 按日期、文件归属、关系字段和并存关系建立事件、人物、君主基线。
3. 分开完成书目逐篇映射和隋唐独立六维审计，形成高优先级候选。
4. 读取《隋书》《旧唐书》《新唐书》《资治通鉴》等可访问正文，做最小 YAML 修订并新增定向测试。
5. 运行校验、Vitest、差异和编码检查，更新总 Todo 并交接五代宋辽夏金。

### 备选方案与取舍

- 不把第177篇钱镠直接算入唐代；若来源和项目分期显示其为唐末—五代跨期，则在报告中单独标注并交下一阶段处理。

## 六、信息基线

### 已核实事实

- 项目分期：`sui` 581–618，`tang` 618–907；五代从907年另列。
- 1988年版历史目录已在上一阶段原始响应中保存，第138篇为“赵绰依法办事”，第176篇为“唐王朝的末日”，第177篇为“海龙王钱镠”。
- 现有数据文件为 `data/events/sui.yaml`、`data/events/tang.yaml`，君主为精选王表而非完整世系。

### 基于证据的判断

- 隋唐应作为统一王朝与唐末结构转折的连续阶段审计；安史之乱前后不能只按盛衰评价叙述。
- 书目篇名只作覆盖索引，科举、均田/租庸调、府兵、对外交流、藩镇和社会经济需独立来源建立基线。

### 尚未验证的假设

- 当前 API 仍可能无法重访；若失败，使用历史原始响应并在报告中降级证据表述。
- 第176篇是唐代主体边界，第177篇只作为五代候选；需以目录与项目分期交叉确认。

### 未决问题

- 隋唐是否已有足够制度和边疆事件，需加载器复合统计确认；不先假定缺口数量。

## 七、约束与原则

- 书目只作覆盖索引，史实回到原始史料和可靠研究；传统评价不直接写入事实标题。
- 保护工作区其他改动；目标 YAML 只做最小补丁，保留 UTF-8/LF/无 BOM。
- 遇到无法精确系年的跨年经历，使用年份级或人物简介并写争议，不伪造日期。
- 不处理1840年以后近代内容，不运行 `npm run build`。
