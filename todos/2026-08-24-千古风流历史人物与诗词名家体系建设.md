## 一、背景

1. **通史骨架与微观生命的互补**：
   - 本项目《上下五千年》已搭建起覆盖先秦至当代的编年史时间轴、朝代演进、历代帝王政权以及中外平行文明对照体系。宏观历史骨架已基本成型。
   - 历史的主轴不仅是政权更迭与重大战役，更有鲜活生动的个体生命轨迹。特别是诗人、词人、思想家、名将与科技大家，承载着中华文明极具感染力的精神底蕴。
2. **现状与资产基线**：
   - 现有 `data/figures.yaml` 共收录 173 位基础历史人物（政治 77、军事 37、思想 25、文学 21、科技 8、艺术 5），目前仅支持简要卡片展示；实际字段为 `id, name, birth, death, field, note, confidence, dispute, related_dynasties`。
   - 首页 `src/pages/index.astro` 已预留 `✍️ 千古风流 · 诗词名家`（文人年谱、名篇佳作与人文足迹）专栏入口，当前状态为 `upcoming`（规划中）。
3. **发展诉求**：
   - 用户明确提出：在朝代与编年体系基本就绪后，启动“人物篇”；重点扩充诗人、词人及跨领域名家，并建立兼具“生平年谱、创作情境代表作、人文行迹地图、文人朋友圈社交网络、文史考评”的深度人物详情页（以李白等为典范）。
   - 为确保长期演进不烂尾、数据可维护、与现有长卷无缝互联，需建立严谨的架构规范与分阶段实施档案。
4. **现有需求缺口**：
   - 原方案虽以“历史人物与诗词名家”为题，但样板、入口文案和批量计划明显偏向唐宋诗词人物，尚未定义政治、军事、思想、科技、艺术、宗教、教育、实业等人物如何进入同一体系。
   - 尚未明确先秦、秦汉、魏晋南北朝、隋唐、宋辽夏金、元明清、近代、现代的边界、跨期人物归属规则，以及女性、少数民族、地方名家、宗教人物、海外华人等群体的收录原则。
   - 尚缺少“读者熟悉篇目覆盖”和“不依赖篇目的历史完整性审计”两套相互独立的基线，容易把知名度、文学性或单一书目误当成完整性。
   - 生卒年精度、作品归属、关系证据、历史地名坐标、现代评价、来源引用、正文与图片版权等字段尚未形成可执行规范。

## 二、目的

1. **建立多维立体的人物标签与检索体系**：定义涵盖“主领域 + 身份体裁 + 流派群组”的分类规范，既支持长卷轻量着色，又支持细颗粒度专题检索（如“盛唐边塞诗人”、“唐宋八大家”、“宋代女词人”、“明末科技名家”等）。
2. **打造沉浸式人物详情页（以李白为样板）**：实现个人生命年谱与时代大势对照、带情境的诗词名篇鉴赏、人文行迹足迹地图可视化、文人朋友圈社交关系图谱及历代考评。
3. **实现通史长卷与人物专页的双向深度打通**：长卷与朝代页可一键下钻到人物详情，人物年谱大事可一键回溯对应年份的天下大势。
4. **确立金字塔梯队推进机制**：顶流名家全景精修、中坚人物标准档案、通识人物轻量索引，保障数据高质量、可持续扩展。
5. **建立历史人物全域覆盖方法**：在诗词名家样板之外，形成覆盖各时期、领域、地域与代表群体的收录矩阵，避免专题长期退化为“唐宋诗词人物库”。
6. **建立可审计的史料、版权与不确定性体系**：每条关键生平、作品归属、足迹和关系均可追溯；事实、推断、传说、争议和现代再阐释分层展示。
7. **保证长期工程质量**：数据、路由、互链、SEO、无障碍、移动端、空数据降级和性能均有自动化或最小人工验收依据。

## 三、方案

### 推荐方案

采用“三层数据结构 + 双层内容审计 + 金字塔渐进推进 + Astro 静态生成（SSG）”方案：

```mermaid
graph TD
    A[data/figures.yaml 全局索引] -->|基础索引与长卷嵌入| B[长卷/朝代页轻量卡片]
    A -->|has_detail 与稳定 id| C[data/figures/detail/{id}.yaml 深度档案]
    C -->|Astro 动态路由 /figure/{id}| D[独立人物全景详情页]
    D -->|双向路由互链| E[年份专页 src/pages/year/[year].astro & 朝代页 /dynasty/{id}]
    D -->|足迹与关系网络| F[GIS行迹地图 & 社交图谱]
    G[书目读者预期覆盖表] --> H[人物候选与缺口清单]
    I[独立历史完整性审计表] --> H
    H --> C
```

1. **三层数据结构体系**：
   - **L1 基础索引库（`data/figures.yaml`）**：保留现有轻量字段和 `related_dynasties`，按兼容迁移方案扩展 `roles`（如 `[诗人, 辞赋家]`）、`tags`（如 `[盛唐, 边塞]`）、`has_detail: true/false`。`field` 继续作为主领域兼容字段，多领域信息放入详卷 `fields`，不得用带价值判断的绰号替代事实标签。
   - **L2 结构化人物详卷（`data/figures/detail/{id}.yaml`）**：每个文件使用稳定 `schema_version`，至少覆盖以下语义；具体字段形状由 TASK-001 固化并以测试为准：
     - `profile`：姓名、异名、字、号、性别、族属/地域（仅有可靠依据时）、籍贯、出生地、逝世地、官职/身份、主领域与跨领域标签。
     - 生卒信息：`birth/death`、`birth_precision/death_precision`、日期范围或未知状态；不得为了通过必填校验伪造精确年份。
     - `timeline`：人生阶段与关键事件分层，记录起止时间、时间精度、地点、事件引用、事实摘要、来源、置信度和争议；统一使用 `timeline`，不再与 `periods` 混用。
     - `works`：标题与异名、体裁、创作时间/范围与精度、地点、背景、关联历史事件、作者归属可信度、来源、原文/摘录显示策略、版权状态、注释、主题、艺术特点和后世影响。
     - `footprints`：历史地名、现代对应地、坐标、坐标来源与精度、到访时间、地点类型、到访证据、推定状态、纪念地标识及路线顺序。
     - `relations`：关系类型、源人物、目标人物、方向、起止时间、证据、置信度和争议；区分可证实交往、同一社群、思想影响与后世附会。
     - `reception`：分开记录同时代评价、历代文学/史学批评、近现代学术研究、教科书与公共文化评价、影视/网络形象；记录评价者、时间、来源、引文边界与版权。
     - `sources/media/version_notes`：来源字典与引用 ID、图片/地图许可和署名、资料版本、修订说明及最后核验时间。
   - **L3 页面渲染与交互层**：
     - `src/pages/figures/index.astro`：千古风流·名家汇聚总览（多维筛选器：朝代/领域/体裁/流派）。
     - `src/pages/figure/[id].astro`：人物独立全景详情页。
2. **分级金字塔推进机制**：
   - 第一梯队（全景精装修，20~30人）：李白、杜甫、苏轼、李清照、屈原、陶渊明、辛弃疾、王维、白居易、诸葛亮、司马迁、王阳明、岳飞等。
   - 第二梯队（标准档案，100~200人）：孟浩然、高适、李商隐、杜牧、柳永、欧阳修、陆游、徐霞客、李时珍等。
   - 第三梯队（轻量索引）：其余历史通识人物。

3. **双层内容审计与候选生成**：
   - **书目读者预期层**：固定使用《上下五千年（上、中、下）》林汉达、曹余章、少年儿童出版社 1988 年 9 月版作为篇目覆盖索引，记录篇号、篇名、时期、核心人物/事件、项目承载 ID 和“已覆盖/部分覆盖/缺失”。该书只帮助发现读者熟悉主题，不是史实权威或收录上限；只保存书目元数据与篇名，不下载、复制受版权保护的正文。
   - **独立历史完整性层**：不依赖上述目录，按时期边界、政权与制度、战争外交与迁徙、经济社会与环境、思想宗教教育、科技文化、代表人物与群体等维度建立人物候选；分别标记“已覆盖/部分覆盖/缺失/不适用/待核验”。
   - 两张表分开统计，合并为候选清单后按历史影响、解释链价值、代表性、证据质量和当前重复度排序；只能声称“本轮定义范围内已审计”，不得声称绝对完整。

4. **地理、关系和来源复用策略**：
   - 人物足迹优先复用 `data/geography/china_geo.json`、`dynasties_geography.json`、`historical_routes.json`、`provinces_config.json` 的边界、坐标和渲染能力；新增人物地理数据须与既有地理体系建立引用或明确隔离理由。
   - 关系图和足迹图均须支持无数据、少数据、证据不足、移动端和禁用脚本场景的文本降级，不得把推定路线或纪念地渲染成确定到访。
   - 来源采用可复用 source ID，页面显示简明引注并提供完整书目信息；现代注释、翻译、研究观点和图片不得因古典原文进入公版而被误判为可自由复制。

### 方案步骤

1. **冻结范围与覆盖基线**：先完成时代边界、人物类型、特殊群体、分级标准、双层覆盖表和来源/版权规范，避免 Schema 与首批名单由李白样板反向绑架。
2. **规范、加载和校验先行**：定义版本化 Schema、枚举、加载器、校验器与测试夹具；同步处理当前 `birth/death/field` 必填假设和不确定日期的兼容方案。
3. **李白史料审计与样板数据**：先形成生平、作品、关系、足迹的证据表，再编写 `data/figures/detail/li-bai.yaml`，不得直接从通识记忆生成成品。
4. **组件与详情页分步建设**：先完成可独立测试的年谱、情境诗卡、关系网、足迹图和来源组件，再组装 `src/pages/figure/[id].astro`，同时完成空数据、响应式与无障碍降级。
5. **全站双向路由联动**：在 `src/pages/dynasty/[id].astro`、实际年份路由 `src/pages/year/[year].astro`、时间轴卡片中注入人物详情跳转；详情年谱仅在引用年份页真实存在时生成链接。
6. **人物总览聚合页建设**：开发 `src/pages/figures/index.astro`，支持时期、领域、身份、体裁、地域、性别等已核实维度的组合筛选，并激活首页入口。
7. **批量扩充与体系校准**：首批统一为杜甫、苏轼、李清照、辛弃疾；完成后复核 Schema 是否对非文学人物公平，再扩展屈原、司马迁、陶渊明、诸葛亮、李时珍等跨领域样本。
8. **质量门禁与维护规范**：完成引用、路由、版权、SEO、JSON-LD、无障碍、移动端和性能验证，并形成后续人物接入清单。

### 备选方案与取舍

- **备选方案 A（全量 Markdown 长文叙述）**：每个人物写一篇 `.md` 文章。
  - *放弃原因*：非结构化 Markdown 难以自动化提取“行迹地图坐标”、“社交网络关系图”、“创作年份与大事件联动”，丢失了数据驱动与知识图谱的优势。
- **备选方案 B（单一大 YAML 文件堆砌所有人物所有诗作）**：把全景数据全部塞入 `data/figures.yaml`。
  - *放弃原因*：单文件体积过大（数万行），冲突风险高，构建加载慢。采用独立文件拆分 `data/figures/detail/{id}.yaml` 架构更清晰。
- **备选方案 C（先做页面、后补来源与 Schema）**：以视觉样板驱动字段补丁。
  - *放弃原因*：会把李白特有结构固化为全人物模型，也会使来源、日期精度、版权和引用完整性只能事后补救。

## 七、约束与原则

- **严格考据与信史边界**：历史生平与争议必须严加区分（如李白出生地西域碎叶与江油说、死因病故与捉月传说均需注明文献出处与争议）。
- **证据分层**：书目篇名只用于覆盖发现；历史事实优先采用原始文献、出土材料、官方档案/博物馆资料和可靠学术研究。搜索摘要、聚合百科和模型记忆不能单独支撑重要结论。
- **精度诚实**：无法可靠确定生卒年、创作年、路线或关系时，保留范围、约数或未知状态；不得为满足必填字段而编造单年日期、坐标或关系。
- **版权与许可**：只保存必要的合法摘录、书目元数据和链接；每张图片、地图、现代引文、注释和译文记录权利状态、来源、作者/机构和署名要求。
- **兼容现有长卷架构**：严禁破坏现有 `loadAll()`、`validate.js`、`dynasty/[id].astro` 及时间轴组件的正常运行。
- **数据结构强校验**：所有新增 YAML 文件必须进入统一加载与校验链路；缺少关键字段、非法日期/坐标、重复条目、断链引用、缺失来源或权利状态不明时按风险报错或警告。
- **可访问与可降级**：地图和关系图不能是唯一信息载体；颜色、图形、悬停和拖拽之外必须有文本、键盘与屏幕阅读器可用路径。
- **最小修改与工作区保护**：执行阶段只修改当前任务所需文件，先核对未提交改动、编码、BOM 和换行；不得清理或覆盖无关改动。
- **验证边界**：优先运行 `npm run validate`、相关 Vitest、Astro 静态检查和最小手动验证；禁止由代理执行 `npm run build`，未运行的检查不得描述为已通过。
