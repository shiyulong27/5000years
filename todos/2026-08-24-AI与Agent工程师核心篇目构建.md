## 一、背景

【十丘】（TenQiu Codex）原定位为“横贯五千年历史长卷与通识百科”，随着学科启蒙（语文、数学、英语）与前沿科技模块的扩展，亟需增加面向现代化程序员、大模型开发者、Agent 架构师以及 Dify 工作流工程师的核心技术篇目。

初学者在接触大模型工程时，普遍面临术语晦涩、链路碎片化（不知道 Embedding、RAG、Re-rank、Memory、Agent 之间如何协同）等痛点。因此，需要打造一套既能让**完全零基础小白**秒懂、又能满足**大厂架构师**深层落地与面试通关的 8 阶渐进式完整知识宝典。

---

## 二、目的

1. **建立 8 阶渐进式心智模型**：8 阶指 8 个知识模块；面试题作为独立附录，不再伪装成第 8 阶知识模块。
2. **分层知识呈现**：每个模块同时提供【💡 小白人话通俗解读】、【📘 正式概念与架构】、【⚙️ 底层原理】、【💻 最小代码】、【🧪 实验】、【🧯 生产避坑】与【✅ 自测题】。
3. **集成交互式实验小工具**：提供 2D 向量相似度计算器与 RRF 排名融合模拟器，增强动手实操体验。
4. **高质量面试刷题库**：收录 10 道大厂高频深度真题，配备实时搜索、分类筛选与掌握状态持久化。

## 三、方案

### 推荐方案
基于 Astro 5 纯静态架构与响应式设计，采用数据与视图解耦模式：
- 知识模块结构化存储在 `src/data/ai/knowledge_modules.json`；
- 面试题库结构化存储在 `src/data/ai/interview_questions.json`；
- 定制现代科技风样式表 `src/styles/ai.css`；
- 在 `src/pages/ai/index.astro` 实现响应式 8 阶路线图、章节内容渲染、交互实验与面试题刷题台；
- 在十丘门户首页 `src/pages/index.astro` 挂载入口卡片与页脚导航。

### 方案步骤
1. **课程建模**：先定义 8 阶课程、前置依赖、章节模板、术语词典、代码示例与来源字段，再扩充知识数据；
2. **样式开发**：设计 Roadmap 路线图、通俗比喻卡片（Analogy Card）、公式排版、终端代码框及刷题控制台；
3. **页面与交互**：构建 `/ai/` 专页，编写向量度量与 RRF 计算器、面试题折叠展开、搜索与 localStorage 掌握状态保存逻辑；
4. **内容与渲染实现**：补齐 Markdown/公式/代码/列表的安全渲染，增加章节级导航和学习完成状态；
5. **首页挂载与全站验证**：更新 `src/pages/index.astro`，执行相关静态检查、单测与轻量验证；不得把 `npm run build` 作为本轮默认验证。

### 备选方案与取舍
- **备选方案**：将所有内容平铺在单篇 Markdown 中展示。
- **放弃原因**：纯文本 Markdown 缺乏交互性（无法进行 RRF 实时计算、无法做面试题分类搜索与掌握状态打勾，也无法呈现现代科技风视觉体验），故选择组件化 Astro 页面。

## 六、信息基线

### 已核实事实
- Astro 模板中 JSX 会将裸 `{` 和 `}` 解析为 JavaScript 表达式，因此公式与代码文本必须转义为 `&#123;` / `&#125;` 或纯文本表达式；
- 项目运行 `npm run build` 需串联跑通 `scripts/validate.mjs` 校验与 `vitest` 测试。
- `knowledge_modules.json` 当前包含 8 个模块、19 个小节；第 3～7 阶每阶只有 2 个小节，整体更接近导览页而非完整课程。
- `src/pages/ai/index.astro` 当前使用 `white-space: pre-line` 直接输出 `sec.content` 与 `q.coreAnswer`，不会解析其中的 Markdown 粗体、反引号代码或 LaTeX 公式。
- 当前专门交互实验只有 2D 向量计算器和 RRF 计算器；未发现针对 AI 数据、内容渲染和交互的专门测试。
- OpenAI 官方 Agent 文档将 running agents、sandbox、orchestration/handoffs、guardrails/human review、results/state、observability 与 evaluation 分开描述；现有内容只覆盖其中少数概念。
- OpenAI 官方 Evals 文档将评测拆为任务定义、测试输入、结果分析迭代，并区分数据 Schema 与 testing criteria/graders。

### 基于证据的判断
- Dense + Sparse + Re-rank 是常见工业方案，但不能写成所有场景的唯一事实标准；应说明召回规模、延迟、模型、数据和成本约束。
- Parent-Document 是解决“检索粒度与生成上下文粒度矛盾”的一种有效方案，不应写成普遍最优解；需要与 Sentence Window、Contextual Retrieval、Hierarchical Retrieval 等方案比较。
- “Harness”需要拆分为 Runtime Harness 与 Evaluation Harness；当前第 6 阶只覆盖 Evaluation Harness 的部分内容。
- 面向小白的路线必须先补软件工程、数学、机器学习和 LLM 基础，否则直接进入 Embedding 会产生明显认知断层。

### 尚未验证的假设
- 具体 Markdown/LaTeX 渲染方案尚未选定，需要结合 Astro 5 的构建方式、依赖许可、XSS 防护和静态输出要求验证。
- Dify 节点、变量语法、DSL 和 API 细节会随版本变化，正式写入前需要锁定版本并记录官方来源。
- 是否新增独立章节页面，还是继续使用单一 `/ai/` 长页面，尚未决定；需要根据内容体量、移动端可读性和站点导航验证。

### 未决问题
- 8 阶是否采用“8 个知识模块 + 面试附录”的统一口径：建议采用，不阻塞 TASK-011。
- 是否为零基础读者增加 Python/TypeScript 与 HTTP/Docker 先修页：建议增加，需在课程数据模型中明确位置。

### 16.2 每个教学小节的统一内容 Schema

后续数据模型至少支持以下字段；具体字段名由 TASK-011/TASK-020 实现时结合 Astro 渲染确定：

1. `id`：稳定章节编号，不随标题变化。
2. `title`、`summary`、`difficulty`、`estimatedMinutes`。
3. `prerequisites`：前置章节和需要会的概念。
4. `learningObjectives`：完成后能解释、能实现、能排查什么。
5. `plainExplanation`：小白解释和生活比喻，但不得用比喻替代正式定义。
6. `formalDefinition`：正式概念、适用边界和反例。
7. `architecture`：流程、组件、输入输出、状态和失败路径。
8. `principles`：必要的数学、算法、协议和复杂度说明。
9. `codeExamples`：最小可运行或可理解代码，标注语言、依赖和预期输出。
10. `labs`：交互实验、输入范围、结果解释和异常输入。
11. `pitfalls`：常见误解、绝对化说法、生产事故和排查顺序。
12. `selfChecks`：选择题、判断题、简答题和实践题，附错误解释。
13. `sources`：官方文档、论文或权威一手来源，记录标题、URL、访问日期、版本和支撑结论。
14. `versionNotes`：模型、框架、Dify 或 API 的适用版本与变更风险。
15. `completionCriteria`：读者达到什么可观察结果才算学会。

### 16.3 Stage 0：零基础先修章节蓝图（TASK-012）

#### S0-01 认识完整 AI 应用，而不是只认识“大模型”

- 学习目标：区分用户界面、业务后端、模型 API、向量库、关系数据库、缓存、消息队列、对象存储、工具服务和观测系统。
- 必讲内容：请求从浏览器到模型再返回的完整链路；训练与推理；模型与 AI 应用；同步与异步；本地、云 API 和私有部署的区别。
- 最小实验：给出一条聊天请求的流程卡片，让读者按执行顺序排列组件。
- 自测标准：能够解释“模型不会自己访问数据库，必须由应用或工具层执行”的原因。

#### S0-02 编程最小基础：变量、函数、集合、错误和模块

- 学习目标：能阅读后续 Python/TypeScript 示例，不要求先成为专业程序员。
- 必讲内容：字符串、数字、布尔值、数组/List、对象/Dictionary、条件、循环、函数、模块、异常处理、环境变量。
- 最小代码：读取用户问题、调用一个函数、处理成功与失败结果、输出 JSON。
- 常见错误：把 JSON 字符串当对象、忽略空值、吞掉异常、把密钥硬编码进代码。
- 自测标准：能修改示例参数，并能说明 `try/catch` 或 `try/except` 的作用。

#### S0-03 命令行、文件路径、Git 与依赖

- 学习目标：能克隆项目、安装依赖、运行脚本、读取错误日志和查看差异。
- 必讲内容：当前目录、绝对/相对路径、文件编码、环境变量、包管理器、Git 工作区/暂存区/提交、`.gitignore`。
- 最小实验：查看当前目录、运行一个脚本、用 `git diff` 检查一处文本修改。
- 安全边界：不得让小白照抄破坏性删除命令；明确密钥、日志和个人数据不能提交。
- 自测标准：能解释“代码、依赖、配置和运行时环境”为什么缺一不可。

#### S0-04 HTTP、API、JSON 与流式输出

- 学习目标：理解应用怎样向模型服务发请求并接收结果。
- 必讲内容：URL、Method、Header、Body、状态码、认证、超时、重试、REST、JSON、SSE/Streaming、Webhook。
- 最小实验：展示一个脱敏的请求/响应，定位请求头、模型名、消息、状态码和错误体。
- 常见错误：把 401 当模型错误、无限重试 429/500、不设置超时、流结束前解析不完整 JSON。
- 自测标准：能根据 400、401、404、429、500 判断优先检查位置。

#### S0-05 数据库、缓存、队列和对象存储

- 学习目标：知道不同数据为什么不能全部塞进向量数据库。
- 必讲内容：关系数据库、文档数据库、向量数据库、Redis 缓存、消息队列、对象存储；主键、索引、事务、TTL 和最终一致性。
- 最小实验：将用户、原始 PDF、文档块、Embedding、会话状态和任务消息分别放入合适存储。
- 自测标准：能解释向量数据库不适合替代订单事务数据库。

#### S0-06 并发、异步任务、超时和幂等

- 学习目标：理解为什么 AI 应用比普通表单请求更容易出现慢请求和重复执行。
- 必讲内容：同步/异步、并发/并行、Promise/async-await、Worker、队列、超时、取消、重试、指数退避、幂等键。
- 最小实验：模拟同一工具请求执行两次，比较有无幂等保护的结果。
- 自测标准：能说明“重试一次转账工具”为什么可能造成严重事故。

#### S0-07 Docker、沙箱和运行环境

- 学习目标：理解代码运行在哪里，以及为什么 Agent 执行工具需要隔离。
- 必讲内容：镜像、容器、端口、Volume、环境变量、CPU/内存限制、网络权限、只读文件系统、临时目录和沙箱。
- 最小实验：通过架构图比较“直接在宿主机运行未知代码”和“受限容器运行”的风险。
- 自测标准：能列出至少三项沙箱限制：文件、网络、资源、时间或权限。

#### S0-08 数学最小基础：向量、矩阵、概率与统计

- 学习目标：为 Embedding、Attention、采样和评测指标建立最低数学基础。
- 必讲内容：标量、向量、维度、模长、点积、夹角、矩阵乘法直觉、概率分布、均值/方差、条件概率、抽样、百分位数。
- 最小实验：继续使用 2D 向量计算器，但增加零向量、反方向和不同模长案例。
- 自测标准：能解释余弦相似度为什么关注方向，以及平均延迟为什么不能代替 P95/P99。

#### S0-09 机器学习最小基础

- 学习目标：理解模型是怎样从数据中学习，而不是把模型描述成数据库。
- 必讲内容：特征、标签、参数、训练/验证/测试集、损失函数、梯度下降直觉、过拟合、泛化、数据泄漏、分类/回归/生成。
- 最小实验：用“背答案”和“学规律”比较训练集高分但测试集失败的过拟合现象。
- 自测标准：能解释为什么不能用测试集反复调 Prompt 后仍声称它是独立测试集。

#### S0-10 Transformer 前置直觉

- 学习目标：在进入 Stage 1 前理解 Token、Embedding、位置、Attention 和逐 Token 生成之间的关系。
- 必讲内容：文本切 Token、Token 转向量、位置编码、Attention 的查询/键/值直觉、层叠变换、Logits、概率分布和采样。
- 最小实验：提供一个简化的“词语关注谁”注意力权重表，不宣称它等同真实模型内部完整机制。
- 自测标准：能按顺序复述“文本 → Token → 向量 → 多层计算 → 下一个 Token 概率 → 采样输出”。

#### S0-11 安全、隐私、版权与成本意识

- 学习目标：从第一阶段开始建立生产边界，而不是学完技术后再补安全。
- 必讲内容：API Key、PII、日志脱敏、数据保留、租户隔离、最小权限、版权来源、Token 成本、调用限额和预算告警。
- 最小实验：从一段请求日志中识别密钥、手机号、身份证、内部 URL 和用户文档等敏感信息。
- 自测标准：能列出哪些数据不能直接发送给第三方模型，以及需要哪些授权或脱敏措施。

#### S0-12 Stage 0 综合实验与过关门槛

- 综合实验：阅读一个最小 AI 应用的伪代码和架构图，识别 UI、API、模型、状态库、工具和日志；根据错误码定位问题；将不同数据放入正确存储；为一个有副作用的工具补超时和幂等保护。
- 知识验收：基础选择/判断题正确率建议达到 80%，但不得把该比例作为生产系统通用质量门禁。
- 实践验收：读者能独立解释一次模型 API 调用，能修改输入并读懂成功/失败输出，能指出密钥与个人数据风险。
- 进入 Stage 1 条件：不要求掌握复杂算法，但必须能阅读基础代码、JSON、架构图和错误信息。
